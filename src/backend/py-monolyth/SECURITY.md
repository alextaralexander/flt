# Security Policy

## Поддерживаемые версии

Это шаблон-boilerplate. Уязвимости принимаются для актуальной ветки `main`/`master`.

## Сообщить об уязвимости

Не открывайте публичный issue для уязвимостей. Сообщайте приватно команде сопровождения
(внутренний канал безопасности / ответственному за репозиторий). Укажите:

- описание и потенциальное влияние;
- шаги воспроизведения (PoC по возможности);
- затронутые версии/коммиты.

Ожидаемое время первичного ответа — несколько рабочих дней.

## Практики безопасности в этом репозитории

- **Секреты** монолит читает только из переменных окружения (ADR-013): в docker-compose — `.env`,
  в Kubernetes — Secret, который External Secrets Operator создаёт из Vault; никогда — из кода,
  конфигов или тестов. Значения в `envs/*` и `.env.template` несекретные; фиксированные тестовые
  значения стенда local помечены `# pragma: allowlist secret`.
- **Статический анализ**: `make security` запускает `bandit` (поиск небезопасных конструкций)
  и `detect-secrets` (поиск утечек секретов). Оба подключены в pre-commit.
- **Базлайн** известных/ложных срабатываний секретов — `.secrets.baseline`. Обновляется командой
  `uv run detect-secrets scan > .secrets.baseline` после ревью изменений.
- **Зависимости** фиксируются через `uv.lock`; обновляйте осознанно и пересобирайте lock.
- **Авторизация** — JWT + permissions (`app/core/security/`). Не ослабляйте проверки прав
  ради удобства разработки в коде, попадающем в `main`.
- **Логирование** не должно содержать токены, пароли и чувствительные payload-данные.

## Чек-лист перед коммитом

- [ ] `make security` без новых находок.
- [ ] Нет секретов в diff (pre-commit это проверит).
- [ ] Изменения прав доступа осознаны и покрыты тестами.
