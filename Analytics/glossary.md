# Глоссарий FLT

> Единые термины для ТЗ, кода и UI проекта Foreign Language Trainer.
> Источники: [FLT_BRD.md](BRD/FLT_BRD.md), [SDD_plan.md](BRD/SDD_plan.md), [CLAUDE.md](../CLAUDE.md).
> Версия 0.8 от 2026-10-11, статус: **draft**.

## Назначение и правила использования

1. В ТЗ, спецификациях модулей, системных спецификациях, ADR, тестах и строках UI используется **только термин из этого глоссария** в форме из колонки «Термин (RU)». Если нужного термина нет — он сначала добавляется сюда, затем используется.
2. Колонка **EN (в коде)** — обязательное имя для идентификаторов: модулей, пакетов, таблиц и колонок PostgreSQL, префиксов ключей Redis, топиков Kafka, ключей i18n, REST-ресурсов, схем Pydantic, имён компонентов frontend. Форма записи: `snake_case` для backend, таблиц, топиков и ключей i18n; для REST-ресурсов — `kebab-case` во множественном числе (`/api/v1/learning-plans`); для компонентов React — `PascalCase`. Имя из этой колонки нельзя заменять синонимом.
3. Слова из колонки **«Не использовать»** запрещены в ТЗ, коде и UI в соответствующем смысле. Исключение — дословные цитаты BRD.
4. Колонка **«Где встречается»** — ID пунктов BRD (реестр в Приложении А SDD_plan.md), системных спецификаций (SYS), ADR и открытых вопросов (`OQ-NN` — у ⚠-терминов, правило 5), а также модули из карты модулей (Приложение В SDD_plan.md). EN-термины модулей совпадают с именами модулей.
5. Знак **⚠** перед термином означает, что смысл термина в BRD неоднозначен: дано рабочее определение, формулировка вопроса приведена в колонке «Определение» после слова «Вопрос». Каждый такой вопрос заносится в реестр открытых вопросов `Analytics/open-questions.md`, его ID `OQ-NN` указывается в колонке «Где встречается»; после решения знак ⚠ снимается и определение уточняется. До решения вопроса термин используется в рабочем значении.
6. **Как добавить термин**: добавить строку в тематический раздел (все пять колонок) и строку в алфавитный указатель EN → RU в том же коммите, что и ТЗ, в котором термин впервые используется. При переименовании старое имя переносится в колонку «Не использовать». Спорный термин помечается ⚠ и заносится в `open-questions.md`. Версия глоссария увеличивается при каждом изменении.
7. Язык терминов: RU — для документации, аналитики и UI (через i18n); EN — для кода и идентификаторов (решение пользователя от 2026-10-10).

## 1. Роли

Правило употребления слова «преподаватель». В BRD это слово обозначает два разных понятия. В ТЗ, коде и UI они различаются так:

- **AI-преподаватель** (`tutor`) — LLM-персонаж, который ведёт занятия, общается голосом и имеет аватар. В русских текстах всегда пишется с приставкой «AI-», в коде — только `tutor`.
- **Преподаватель** (`teacher`) — человек, роль «Администратор преподавателя/класса». Слово «преподаватель» без приставки в ТЗ и UI означает только человека. В коде — только `teacher`; полная форма роли в коде — `teacher` (без `class_admin`).
- При переносе пункта BRD в ТЗ смысл уточняется: VIS-03, STU-20–STU-23, STU-28, STU-29, TCH-04 (объект настройки) — AI-преподаватель; TCH-01–TCH-09 (субъект действия), ADM-02 — преподаватель-человек.
